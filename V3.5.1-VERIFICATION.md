## Live Netlify verification checklist

### 1. Deploy only to the development Netlify site

Do not deploy this package over the surviving Golden prototype.

### 2. Verify persistent storage before spending WCL points

Call:

`/api/wcl/corpus?encounter=3182&action=health`

Expected:

- `ok: true`
- `engineVersion: "3.5.1"`
- `storage.kind: "netlify-blobs"`
- `storage.persistent: true`

This health check does not start corpus discovery. If it returns a persistent-storage error, do not press BUILD CORPUS; send the response back for diagnosis.

### 3. Confirm old p0 state is not reused

Before starting a new corpus, call:

`/api/wcl/corpus?encounter=3182`

With no v3.5.1 alias yet, `status:null` is expected. The old v3.5.0 `3182/d5/p0` state should not be surfaced as the active corpus.

### 4. Start the corpus and verify the storage/partition contract immediately

After pressing BUILD CORPUS, inspect the same status endpoint. Expected:

- `engineVersion: "3.5.1"`
- `corpusId: "3182/d5/p4"` for the current Belo'ren default partition
- `partition: 4`
- `resolvedPartition: 4`
- `storage.kind: "netlify-blobs"`
- `storage.persistent: true`

If storage is not `netlify-blobs`, stop. Hosted v3.5.1 intentionally refuses a local fallback.

### 5. Verify discovery expands beyond ranked seeds

Expected phase sequence:

`discover-ranking -> discover-identities -> expand-sources -> wide -> deep -> compile -> complete`

During source expansion inspect:

- `sourceStats.total`
- `sourceStats.guilds`
- `sourceStats.personalUploaders`
- `sourceStats.pagesScanned`
- `sourceStats.reportsDiscovered`
- `candidateCount`

The original Belo'ren ranking produced roughly 146 ranked seed reports. `candidateCount` should be able to grow beyond that as public guild/personal histories are expanded.

### 6. Verify the v3.5.0 WCL contract error is gone

There must not be a repeating error containing:

`You must either provide fightIDs, or provide startTime and endTime`

When Wide begins, successful profiles should make these values grow:

- `processedWideCount`
- `pullCount`
- `aggregate.killPulls`
- `aggregate.wipePulls`

`skippedNoEncounter` may grow and is normal: expanded report history can contain raid reports without this exact encounter/difficulty.

### 7. Verify the circuit breaker

If a genuinely structural error repeats three consecutive times, expected state is:

- `status: "paused"`
- `pauseReason: "systemic-error"`

The builder should stop spending WCL points until manually resumed.

### 8. Verify the UI is pull-first

The Mechanics corpus card should show wording such as:

- `WIDE CORPUS 87 / 5000`
- `X reports profiled · Y independent sources`
- `DEEP SAMPLE ...`
- selector options ending in `target pulls`
- `ENRICH +500 PULLS` after completion

Discovery phases should move the progress bar rather than showing a permanent 0% Wide state.

### 9. Verify persistence

Once `pullCount > 0`:

1. Pause the corpus.
2. Hard refresh/open the status endpoint in a new tab.
3. Verify candidate, processed, source and pull counts are retained.
4. Resume and verify the same job continues rather than starting from zero.

Persistence across a later deployment of the same Netlify site is also expected because the state lives in Netlify Blobs.

### 10. Model endpoint behavior

Early in the build:

`/api/wcl/corpus?encounter=3182&action=model`

may return no model. That is expected before compilation.

At compile/complete, inspect `model.status`, `publishChecks` and `thresholds`. A `candidate` model is valid when one or more publication gates are still unmet; it must not be silently treated as a published encounter pack.

### 11. Check the partition-window heuristic

Inspect `partitionWindowStart`. It should be close to the beginning of the current partition's ranked seed history. It is deliberately calculated from current-partition seeds minus two days because WCL does not expose an authoritative partition start timestamp through the `Partition` schema.

## Operational note

The current Netlify implementation is checkpointed but client-driven: the browser calls one corpus step at a time. You can pause/close and later resume without losing persisted progress, but the job does not continue indefinitely in the background after the page is closed.
