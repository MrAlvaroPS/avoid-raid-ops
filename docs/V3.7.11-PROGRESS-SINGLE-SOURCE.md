# v3.7.11 — Progress single-source migration

## Root cause fixed

`wcl-runtime.js` and the dedicated Progress runtime were both writing to Progress. The legacy adapter used current-report `payload.progression` while the newer runtime used encounter history, so the command bar could say `25 / 51` while the SVG was overwritten with ~13 current-report pulls. The same dual-writer problem affected Night-over-night and the Stage matrix.

## New ownership

- `History` builds `progress-model-v1` on the server.
- `progress-runtime-v3711.js` is the only writer to Progress.
- On the Progress page it intercepts the legacy `applyProgressPage`, `applyProgressCurve`, `applyHistoryData` and `applyRealProgressMatrix` functions.
- The legacy functions remain available on other pages where they are still needed.
- Browser range changes only redraw the canonical chart and add zero WCL calls.

## Shared model

Every strategic panel now shares:

- one deduplicated canonical pull sequence;
- one global pull numbering scheme;
- one raid-night partition;
- one policy object;
- one server-side formula implementation.

The model exposes invariants and exact-100% diagnostics so input-quality issues can be separated from UI/model inconsistency.
