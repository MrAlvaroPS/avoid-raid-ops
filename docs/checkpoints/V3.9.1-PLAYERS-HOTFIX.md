# v3.9.1 Players hotfix

## Regression fixed

- v3.9.0 removed the legacy roster height cap with an unbounded `overflow: visible` override. This could let the roster dominate the Players grid and visually displace the raider dossier.
- The reconstructed React/Golden Players shell still contained a literal `91%` ROSTER RELIABILITY mock and `Peer median 84%`. React could recreate that shell between overlay renders, so the fake number appeared and disappeared even though no player Reliability profile was published.

## v3.9.1 contract

- Product package: `0.3.9-1-vercel.0`.
- Active Players runtime: `player-intelligence-v391.js`.
- Active correction stylesheet: `raidops-v391.css`.
- Reliability model remains `1.1.0`; no scoring formula, denominator, prior, weight, confidence or publication threshold changed.
- A player is presentation-published only when `status === 'published'`, `publication.publishable === true` and `value` is finite.
- ROSTER RELIABILITY is `—` when there are no genuinely published profiles. Its aggregate is the mean of published values only.
- Historical shell mock content cannot flash as live Reliability: the banner remains hidden until the active Players runtime explicitly takes ownership.
- On desktop, the roster may grow to the measured dossier height. It scrolls internally only if its content exceeds that useful height.
- On stacked layouts, the roster gets a viewport-relative bounded height so it cannot push the dossier arbitrarily far down the page.
- The raider dossier remains the right-column owner on desktop and retains the v3.8.8 evidence/attendance/WHY PENDING functionality.

## Validation

Critical regression coverage verifies dossier/layout behavior, banner ownership, removal of the literal 91% shell value, strict publication gating, runtime liveness, release wiring and the normal v3.9 data contracts.
