# v3.9.2 Players hotfix

## Scope

Presentation/ownership hotfix on top of the v3.9.1 Iris semantic-learning release. Reliability model `1.1.0`, evidence contracts, weights, priors, denominators, confidence and publication thresholds are unchanged.

## Regressions fixed

1. v3.9.0 replaced the legacy roster height cap with unbounded `overflow: visible`. The roster could dominate the two-column Players layout and visually push/displace the raider dossier.
2. The reconstructed Players shell still contained a literal `91%` ROSTER RELIABILITY mock and `Peer median 84%`. React could recreate that shell between real-data runtime renders, so a fake aggregate appeared and disappeared even though no individual Reliability value had been published.
3. The Players overlay was gated only by its data signature. If React recreated the roster/dossier/matrix DOM while the WCL payload remained unchanged, the runtime considered itself up to date and could leave the reconstructed shell in place instead of restoring the real-data dossier.

## v3.9.2 contract

- Package: `0.3.9-2-vercel.0`.
- Active Players runtime: `public/player-intelligence-v392.js`.
- Active correction stylesheet: `public/raidops-v392.css`.
- A player is presentation-published only when `status === 'published'`, `publication.publishable === true`, and `value` is finite.
- `ROSTER RELIABILITY` is `—` when no individual profile is genuinely published.
- When profiles are published, the roster aggregate is the mean of published finite values only.
- The shell itself contains no fabricated roster Reliability number.
- Until the Players runtime explicitly owns the banner node, stale shell value/subtitle content is hidden.
- On desktop the roster consumes the measured dossier height before becoming an internal scroller.
- The dossier remains the stable right-column owner and retains player evidence, attendance and WHY PENDING/SCORE output.
- On stacked layouts the roster receives a viewport-relative bound so it cannot push the dossier arbitrarily far down the page.
- The runtime tracks the actual roster/dossier/matrix node identities. If React rebuilds those nodes without any WCL-data change, the next bounded poll reacquires and rerenders them. This remains observer-free and does not reintroduce DOM mutation feedback loops.

## Compatibility

The v3.9.1 Iris semantic-probe/corpus learning stack remains untouched. Its capability contract stays release `3.9.1`; v3.9.2 changes only Players presentation/runtime ownership and app package metadata.
