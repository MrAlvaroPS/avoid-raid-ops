# AvoiD Raid Ops v3.2 — Domain cleanup + roster intelligence

v3.2 keeps the recovered Golden Master immutable and advances the product in two categories:

1. **domain correctness / scalability**, based on the real Avoid Belo'ren report;
2. **two explicitly approved UI evolutions**: larger telemetry typography and a new Composition roster-intelligence panel.

## Domain changes

### Absolute progression stages
WCL semantic phase IDs may repeat. Belo'ren exposes a sequence like `1 → 2 → 1`, while progression has three absolute stages.

The normalized fight model now stores both:
- `absoluteStageIndex`
- `semanticPhaseId`

P1/P2/P3 analytics use absolute progression stages, so Stage 3 no longer disappears simply because the semantic phase ID returns to `1`.

### Player metric scopes
A player no longer mixes best-pull output with encounter-wide accountability under one ambiguous object.

```text
player.bestPull
  damage / dps / healing / hps / damageTaken / casts

player.encounter
  pulls / raw deaths / meaningful deaths / first deaths / interrupts / dispels

player.character
  gear / talents / CombatantInfo provenance

player.reliability
  value / status / confidence / reason
```

Compatibility aliases remain temporarily for the Golden runtime adapter.

### Death semantics
Deaths are now split into:
- **raw deaths** — every observed friendly death event;
- **meaningful deaths** — WCL Death events using `wipeCutoff: 5`;
- **first deaths** — first relevant death in each pull.

These are intentionally not treated as equivalent to mistakes or preventable deaths.

### Raid sessions instead of raw report history
History now clusters overlapping reports from the same raid period into a `RaidSession` and deduplicates likely duplicate pulls from multiple loggers.

The initial fingerprint uses encounter, absolute start time, duration, progress and tolerances. Report listing is paginated and fight loading remains a separate, concurrency-limited stage.

### Event query hygiene
- mechanic timing asks for **enemy** casts explicitly;
- deaths/interrupts/dispels are scoped to friendlies;
- unfiltered Buff event pagination remains deferred;
- CombatantInfo is fetched independently so roster enrichment cannot take down core telemetry.

### CombatantInfo player profiles
The profile normalizer accepts WCL CombatantInfo/playerDetails data and produces normalized:
- gear / slots / item level / gems / enchants when exposed;
- talents / nodes / ranks when exposed;
- profile coverage metadata.

A `debug=1` telemetry mode exposes only tiny event/profile samples to diagnose WCL's flexible JSON shape without dumping full streams.

## Composition changes

Composition gains a **Roster intelligence** panel while retaining the existing visual language.

For each selected-pull raider it exposes:
- player;
- class and spec;
- role;
- item level;
- equipment coverage / average gear ilvl;
- talent coverage;
- best-pull output;
- **the exact same Reliability field used by Players**;
- first-death / interrupt context.

Clicking a player expands equipment and talent details inline.

Class names are normalized (`DeathKnight` ↔ `Death Knight`, `DemonHunter` ↔ `Demon Hunter`) so class coverage does not produce false missing classes.

## Reliability truth boundary

Reliability is deliberately **not synthesized from incomplete data**. Both Players and Composition read the same `player.reliability` object.

Until mechanics and defensives are classified, the value is `— / PENDING`, not zero and not a mock number.

## Readability

`golden-master/main.css` and deployed `main.css` are unchanged.

A separate `raidops-v32.css` override increases the smallest telemetry/table text to practical desktop sizes while retaining the same hierarchy, spacing language, colors, cards and navigation.

This is an intentional approved visual delta; it does not mutate the Golden Master.

## Golden Master status

The original recovered assets remain immutable. v3.2's deploy shell still uses the Golden `main.js`/`main.css`; data enrichment and controlled UI additions live in the runtime/override layer until the source React build passes a future screenshot-diff gate.
