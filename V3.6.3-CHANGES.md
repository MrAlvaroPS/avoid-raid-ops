# AvoiD Raid Ops v3.6.3 — Vercel build-output collision fix

## Root cause fixed

Vercel's current Nitro guidance explicitly warns that a top-level `/api` source directory is not compatible with Nitro on Vercel because Vercel's build system may compile `/api` independently while Nitro also emits the same app into `.vercel/output`. That double ownership can end with:

`Error: '/vercel/output/functions/__server.func/.vc-config.json' already exists`

v3.6.3 removes the top-level source `/api` directory entirely.

## Route layout

Before:

`api/wcl/*.js`

After:

`routes/api/wcl/*.js`

Public URLs remain unchanged:

`/api/wcl/report`, `/api/wcl/telemetry`, `/api/wcl/history`, `/api/wcl/intelligence`, `/api/wcl/status`, `/api/wcl/corpus`.

Nitro remains the only component that owns Vercel Build Output. Workflow remains integrated through `workflow/nitro`.

## Regression guard

A unit test now fails if a top-level `api/` directory is reintroduced, and architecture verification treats `routes/api/wcl` as the Vercel/Nitro transport layer.
