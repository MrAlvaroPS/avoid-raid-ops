# v3.7.9 — Progress becomes encounter history

## Scope correction

`Progress` is now the strategic / historical encounter view. `Live` remains the current raid-night and between-pull decision surface.

The v3.7.8 `Between-pull RL brief` and selected-pull inspector are intentionally removed from Progress. They were useful interaction experiments but belonged to Live / Pull Lab rather than long-horizon progression.

## Encounter-wide pull history

The existing History query already loads the selected encounter from guild reports. v3.7.9 now preserves a compact, deduplicated `progressionPulls` series from those already-loaded fights.

- same encounter + difficulty
- analytical pulls only
- called-wipe/reset exclusions preserved
- duplicate uploads deduplicated by timestamp + duration + progress
- absolute stage depth retained
- global pull numbers assigned chronologically
- raid-session identity retained

No new browser WCL request is introduced. The History lookback remains 35 days, so this release does not silently increase WCL query breadth/cost.

## Progress UI

### Range controls

- ALL
- LAST 100
- LAST 50
- LAST 25

Ranges now operate on the encounter-wide historical series rather than the current report only. A range that would be identical to ALL is disabled instead of pretending to change the graph.

### Main graph

Shows:

- boss HP remaining per global progression pull
- rolling 10-pull median (5 when the sample is small)
- personal-best breakthroughs
- raid-night boundaries

### Strategic headline metrics

- TOTAL PROG PULLS
- BEST PULL
- LAST 20 MEDIAN
- DEEPEST STAGE REACH
- PULLS SINCE PB

The banner reports a recent progression trend using 20-vs-20 pulls when available, then 10-vs-10 or 5-vs-5 for smaller samples.

### Night-over-night

Uses real History sessions and compares best + median depth between the latest raid nights.

### Stage consistency matrix

The old last-eight-pulls matrix is converted into 20-pull windows. Each cell is the percentage of that window reaching the given absolute stage, making repeatability visible instead of focusing on one pull.

## Safety / architecture

- Corpus remains untouched and in standby.
- No corpus reads/writes were added.
- No WCL request is triggered by changing Progress ranges.
- The implementation is encounter-generic; no Belo'ren-specific logic is introduced.
- v3.7.8 remains as a regression asset but is no longer the active Progress runtime.
