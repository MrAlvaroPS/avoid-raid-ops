# v3.6.2 Hosted Research — deployment and first-run checklist

## 1. Create persistent storage first

In the **same Vercel project** that serves AvoiD Raid Ops:

1. Open **Storage**.
2. Create a **Blob** store.
3. Choose **Private** access.
4. Connect it to the AvoiD project/environment(s) you will use.
5. For a new connection, leave authentication on Vercel's project-scoped **OIDC** path. No manually copied `BLOB_READ_WRITE_TOKEN` is required. Legacy stores that still use that variable remain compatible.

Do not use a Public Blob store for this corpus.

## 2. Keep WCL environment variables

Required:

- `WCL_CLIENT_ID`
- `WCL_CLIENT_SECRET`

Optional/current defaults:

- `WCL_REPORT_CODE=28d9xF7GchL6ZPYt`
- `WCL_GUILD_ID=788166`
- `ANALYSIS_VERSION=3.6.2`

## 3. Vercel build settings

v3.6.2 is Vite + Nitro. It does **not** use the v3.5.1 `public/` static-output override.

Use Vercel auto-detection/defaults:

- Framework: Vite/Nitro auto-detected
- Build command: default or `npm run build`
- Output directory: **blank/default**

There is intentionally no `vercel.json` forcing `outputDirectory: public`.

## 4. Preflight — do this before BUILD CORPUS

Open:

`/api/wcl/corpus?encounter=3182&action=health`

Expected shape:

```json
{
  "ok": true,
  "runtime": "vercel",
  "corpusBuilder": "vercel-workflow",
  "engineVersion": "3.6.2",
  "schemaVersion": 2,
  "workflow": { "enabled": true, "durable": true },
  "storage": {
    "kind": "vercel-blob-private",
    "persistent": true,
    "hostedBuilder": true,
    "consistentReads": true
  }
}
```

If this returns 503, reports an authentication/storage error, or does not report private persistent Blob storage, **do not start a corpus**. A legacy deployment may mention `BLOB_READ_WRITE_TOKEN`; a new OIDC-connected store should not require you to create or paste one manually.

Then open:

`/api/wcl/corpus?encounter=3182`

A brand-new v3.6.2 store should normally return `status:null`.

## 5. Visual check

Open **Mechanics**.

The `Encounter Intelligence Corpus` panel must be the first large panel immediately below the Mechanics page banner, above `Encounter mechanic catalogue`.

The initial selector should offer:

- 1,000 target pulls
- 5,000 target pulls
- 10,000 target pulls

## 6. First hosted run — use 1,000 pulls

Select **1,000 target pulls** and press **BUILD CORPUS**.

The POST response is expected to be HTTP 202 and include a `workflowRunId`.

Within the status endpoint expect:

- `engineVersion: "3.6.2"`
- `corpusId: "3182/d5/p4"` if WCL partition 4 is still the current default
- `resolvedPartition: 4`
- `executionMode: "vercel-workflow"`
- non-null `workflowRunId`
- `status: "running"` or temporarily `"rate-limited"`
- `targetPulls: 1000`
- `deepTargetPulls: 200`

The exact partition must come from live WCL; do not hardcode p4 if WCL has changed it.

## 7. Prove that the browser is not the worker

After the job starts:

1. Note `candidateCount`, `processedWideCount`, `pullCount`, and `workflowRunId`.
2. Close the AvoiD tab completely for a minute or two.
3. Reopen `/api/wcl/corpus?encounter=3182`.

Once discovery has reached profiling, the counts should continue changing without the tab being open. That is the key proof that Vercel Workflow owns execution.

## 8. What healthy progression looks like

Phases should move approximately:

`discover-ranking → discover-identities → expand-sources → wide → deep → compile → complete`

Useful status fields:

- `seedReportCount`
- `sourceStats.total`
- `sourceStats.guilds`
- `sourceStats.personalUploaders`
- `sourceStats.reportsDiscovered`
- `candidateCount`
- `processedWideCount`
- `pullCount`
- `processedDeepCount`
- `deepPullCount`
- `failedCount`
- `skippedNoEncounter`
- `lastFailure`
- `rateLimit`

`skippedNoEncounter` is not a pipeline error: source expansion deliberately discovers some raid reports that do not contain the exact encounter+difficulty.

## 9. WCL rate protection

The builder reserves at least 600 WCL points or 18% of the hourly limit, whichever is larger. If the reserve is reached, status becomes `rate-limited` with `resumeAt`. The durable workflow sleeps until the window is safe again.

Do **not** manually resume a rate-limited run simply to force more WCL traffic. Use PAUSE only if you want to stop research.

## 10. Circuit breaker

Three consecutive identical structural errors auto-pause the job. If you see:

- `status: "paused"`
- `pauseReason: "systemic-error"`

send the compact status response, especially `systemicFailure` and `lastFailure`. Do not repeatedly press RESUME until the query contract is fixed.

## 11. Pause/resume test

During Wide processing:

1. Press PAUSE.
2. Wait for the current small batch to settle.
3. Refresh status and note counts.
4. Wait another 20–30 seconds; counts should remain stable.
5. Press RESUME.

A new `workflowRunId` should appear while all persisted counts continue from the prior checkpoint.

## 12. After 1,000 pulls

The first run is a crawler/storage/workflow validation run. Current auto-publish gates still require more evidence (including 2,500+ Wide pulls and 300+ Deep pulls), so a 1K model may correctly remain `candidate`.

Before enriching to 5K, review:

- number of independent sources
- kill/wipe balance
- failed/error rate
- WCL points per retained pull
- Deep completeness
- candidate mechanic count and validation diagnostics

If those are healthy, use 5K and then 10K. Existing reports/pulls are retained; ENRICH adds to the same partition-locked corpus instead of rebuilding from zero.

## 13. Later Mac migration

The corpus/compiler is not coupled to Vercel Workflow. The future semi-local runner will reuse `server/corpus/` and swap storage/execution adapters. Hosted data can then be exported/imported rather than relearned from scratch.
