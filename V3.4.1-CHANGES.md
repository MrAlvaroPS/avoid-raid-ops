# AvoiD Raid Ops v3.4.1 — analysis quality hotfix

## Talent build fix

- `Spell null` can no longer be rendered.
- `null` is no longer coerced to numeric `0` while normalizing CombatantInfo.
- Raw TraitNodeEntry/node IDs remain hidden.
- Raid Ops now asks Warcraft Logs for `ReportFight.talentImportCode(actorID)` for every player on the selected best pull.
- When WCL returns a canonical Blizzard talent loadout code, Composition shows one useful action:
  **Open exact talent build on Wowhead**.
- Wowhead URL format: `/talent-calc/blizzard/<WCL talent import code>`.

## Reset / run-wipe exclusion

A shared pull-eligibility policy now removes obvious reset pulls from analytical data.

Excluded:
- closed pulls shorter than 20 seconds;
- an explicit Companion-app wipe called within the first 20 seconds;
- stage-1 pulls <=45 seconds with >=95% boss health remaining and essentially no progress;
- with death evidence, stage-1 pulls whose first death is <=12 seconds while boss health remains >=95%.

Kills are never excluded.

Excluded pulls do not enter:
- latest-vs-previous comparison;
- Pull Lab baselines;
- progression median / phase conversion;
- player encounter totals;
- mechanic/blocker analysis;
- raid-night history rollups;
- LIVE latest meaningful pull;
- WCL intelligence event queries.

The WCL fight still exists as raw diagnostic provenance, but is not a normal product metric.

For the supplied report, fight/pull 13 (28.257s, stage 1, 97.06% boss remaining, first death around 7.6s)
is classified as an early reset. Pull 14 therefore compares against Pull 12, not Pull 13.

## LIVE comparison UX

- Empty regressions/improvements no longer repeat the same placeholder three times.
- When there is no regression, a single compact empty state is shown.
- Comparison subtitles explicitly say `previous meaningful pull`.

## Belo'ren intelligence corrections

The v3.4 endpoint exposed event-granularity bugs. v3.4.1 fixes them:

### Ember Rebirth
- `begincast` = opportunity only.
- only an actual `cast` completion = failure.
- no more treating every cast start as a failed egg.

### Radiant Echoes / Voidlight Rupture proxy
- periodic damage ticks are clustered into one player incident.
- a DoT/ticking episode no longer becomes dozens of separate failures.

### Light/Void Eruption
- raid-wide damage fan-out is clustered into one failed-interrupt incident.
- 20 players taking the same blast is one raid failure, not 20 player failures.
- hit players are not individually blamed for failing the interrupt.

### Guardian's Edict
- boss buff application/stacking is now observed-only.
- it is not proof that the tank assignment failed and is no longer scored as a failure.

### Death chains
- player-specific evidence can still link within the normal evidence window.
- raid-wide failures require high/confirmed evidence and <=3s proximity.
- weak global correlations no longer create large numbers of fake linked deaths.

### Current Blocker
- raw event volume no longer dominates blocker ranking.
- scoring now uses recurrence, failure rate where available, recency and capped death evidence.

### Mechanical Accuracy
- temporarily remains PENDING.
- the denominator unit is not homogeneous across all mechanic types yet, so v3.4.1 refuses to publish a misleading percentage.

### Event completeness
- filtered mechanic damage events are paginated instead of silently stopping at the first WCL page.
- Light/Void assignment auras are queried as friendly Debuffs, matching their combat-log semantics in this encounter.
