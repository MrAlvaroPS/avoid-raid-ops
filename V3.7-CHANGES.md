# AvoiD Raid Ops v3.7 — Encounter Discovery Engine

v3.7 changes the corpus project from an ability-pattern miner into a generic encounter-discovery engine. The goal is to learn reusable mechanic semantics from a large WCL corpus instead of hand-authoring every boss/difficulty.

## Encounter discovery

- Detects mirrored/opposite mechanic families such as Light/Void without boss-specific ability IDs.
- Infers persistent mutually-exclusive state dimensions from aura evidence.
- Relates state dimensions to cast/damage families and keeps player blame disabled until per-target alignment is validated.
- Learns cast → enemy aura failure relationships from temporal + kill/wipe evidence.
- Collects enemy buffs and debuffs in new Deep profiles so failure signals such as boss empowerment auras can be discovered generically.
- Uses kill-vs-wipe contrast and deep completion/interruption evidence instead of treating every frequent cast or damage event as a failure.
- Phase-near casts are observational unless stronger evidence proves phase semantics.

## Safer train/holdout

Train/holdout is now split by raid source (guild first, uploader fallback), not by report code. Reports from the same guild cannot leak across training and validation.

The model exposes separately:

- represented sources,
- Deep represented sources,
- train sources,
- isolated validation sources,
- discovered source pool.

## Boss Learned %

The corpus panel now shows **BOSS LEARNED** with an evidence-weighted maturity score and grade:

- DISCOVERY
- LEARNING
- PARTIAL
- STRONG
- MATURE
- VERIFIED

The percentage is explicitly **not** “percent of every mechanic in the game known”. It is model maturity based on:

- data depth,
- holdout quality,
- important signal coverage,
- semantic resolution,
- source diversity.

Critical unresolved signals, unresolved state models, or thin Deep evidence cap the score.

The model also returns a recommendation explaining whether the next useful action is:

- review/publish,
- targeted Deep enrichment,
- diversity-first enrichment,
- wide + Deep enrichment.

## Stronger publication gate

A model can no longer auto-publish only because it has enough pulls and a high aggregate holdout score. It must also satisfy:

- 2,500+ Wide pulls,
- 300+ Deep pulls,
- 250+ Wide reports,
- 50+ Deep reports,
- 50+ represented independent sources,
- 12+ isolated validation sources,
- 50+ validation reports,
- >=66% weighted holdout validation,
- >=82% Boss Learned,
- >=70% semantic resolution,
- >=75% important-signal coverage,
- zero critical unresolved signals.

## Zero-WCL recompile

Existing persisted Blob profiles can be reprocessed by the new compiler without downloading WCL again.

The Mechanics panel exposes:

`RECOMPILE · 0 WCL`

This rebuilds the aggregate, applies source-isolated train/holdout, reruns discovery, and writes a v3.7 candidate model using only existing Private Blob data.

## Corpus UX

- Frozen rate-limit text has been replaced with a countdown derived from `resumeAt`.
- Wide statistics distinguish processed reports, represented sources and discovered source pool.
- Boss Learned component bars show DATA / HOLDOUT / SIGNALS / SEMANTICS / DIVERSITY.
- Enrichment CTA follows the model bottleneck rather than always requesting a blind +500 Wide pulls.

## Runtime compatibility

The curated Belo'ren pack remains a safe fallback until a generated model passes all publication gates. The Golden Master assets remain unchanged.
