# AvoiD Raid Ops v3.3 — Data Truth + Pull Intelligence

v3.3 is a data-integrity release. It does **not** add the Belo'ren mechanic rule pack, Reliability score, Current Blocker classifier or peer benchmark yet. Instead it makes the existing product safe enough for those engines to be built on top of it.

## Release rule

Every visible analytical value must be one of:

- **REAL / OBSERVED** — directly supported by Warcraft Logs.
- **DERIVED** — calculated from observed data with a documented rule.
- **PENDING / N/A / UNAVAILABLE** — not yet defensible.

A Golden Master mock is never an allowed production fallback.

The deploy now has a boot gate: the recovered Golden UI is hidden while WCL data layers load. This prevents the original mock numbers from flashing briefly before the data adapter replaces them. If the critical telemetry layer fails, an explicit WCL data error is shown instead of exposing mock content.

## Pull Intelligence

New engine: `server/analysis/pulls/pull-intelligence.mjs`.

For every closed pull it stores real facts:

- WCL `fightPercentage`
- boss percentage
- duration
- absolute stage reached
- per-pull raid DPS/HPS from WCL Summary
- first death timing
- raw deaths
- meaningful deaths using the death engine / wipe cutoff
- roster fingerprint

The latest pull is compared with:

- previous pull
- median of the previous 3 pulls
- median of the previous 5 pulls
- best pull

Directional labels are intentionally conservative:

- lower `fightPercentage` = deeper progression
- higher stage reached = improvement
- later first death = improvement
- fewer meaningful deaths = improvement
- raid DPS is only called better/worse when both pulls reached the same absolute stage
- raid HPS is observational only because healing demand is encounter-dependent

This now feeds Command Center `What changed?`, LIVE and Pull Lab.

## Composition / CombatantInfo

The misleading raw inventory average seen in v3.2 has been removed from the UI. `itemLevel` from the WCL character/fight is the displayed character ilvl; the arithmetic mean of arbitrary CombatantInfo inventory rows is never presented as character ilvl.

CombatantInfo normalization now:

- filters empty item id `0`
- assigns readable inventory slot names
- keeps item id, item level, gems and enchants when WCL exposes them
- merges CombatantInfo and playerDetails field-by-field
- preserves talents as node / entry / spell / rank facts
- produces a deterministic build fingerprint

### Wowhead

Wowhead is an enrichment/link-out layer, not the combat source of truth.

- item IDs link directly to `wowhead.com/item=<id>`
- spell IDs link directly to `wowhead.com/spell=<id>`
- Wowhead tooltips are enabled for exact item/spell links, including dynamic links added when a roster row is expanded
- when WCL exposes only a talent node/entry and no resolvable spell id/name, Raid Ops links to an explicit Wowhead search instead of pretending that a node id is a spell id

This keeps Raid Ops independently reproducible from WCL while giving the RL a one-click path to deeper object/spell information.

## Visible mock removal

The runtime now explicitly neutralizes Golden-only analysis and removes/marks pending areas that do not yet have a real engine, including:

- Kill Readiness
- Current Blocker
- Wipe Signatures
- mechanic failure/accuracy claims
- defensive availability/preventability claims
- Reliability
- peer kill benchmark values
- composition recommendations
- synthetic player trend curves
- synthetic Pull Lab mechanic/defensive metrics

The recovered mock datasets remain in the source reconstruction only as fidelity fixtures. They are not valid production data paths.

## Golden Master

The immutable Golden assets remain byte-for-byte unchanged:

- `main.js`
- `main.css`
- `favicon.svg`
- `og.png`

v3.3 changes only the data/runtime overlay and the intentional legibility/roster overlay stylesheet introduced after the Golden recovery.
