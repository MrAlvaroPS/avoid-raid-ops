# AvoiD Raid Ops v3.1 — deployable architecture checkpoint

This release keeps the recovered Golden Master visual layer immutable and moves the active WCL backend onto the v3 modular architecture.

## Fixed from the live Belo'ren validation
- Player roles now come from WCL Summary composition (`tank` / `healer` / `dps`) instead of the incorrectly parsed `playerDetails` shape.
- Death / interrupt / dispel counts are derived from real event rows, not nonexistent `total` fields.
- Observed mechanics are extracted only from `DamageTaken.entries[].abilities`; player names can no longer be promoted to mechanics.
- Numeric `ability` IDs in WCL event payloads are supported, enabling first-cast timestamps.
- Unfiltered Buff events are no longer downloaded by the thousands. Buff-event reconstruction will be spell-filtered once defensive rule packs exist.
- Two-phase encounters show P3 as `N/A` rather than pretending a third phase exists.

## History architecture
History is now two-stage:
1. list inexpensive report metadata;
2. fetch encounter fights only for a bounded set of candidate reports, with concurrency 4.

This avoids the previous GraphQL complexity of 111001 (>50000).

## Routing
`deploy-preview/public/_redirects` explicitly reserves all four `/api/wcl/*` routes before the SPA fallback.

## Golden Master
The deployment still serves the exact recovered `main.js`, `main.css`, favicon and OG image. `wcl-runtime.js` remains a data adapter only.
