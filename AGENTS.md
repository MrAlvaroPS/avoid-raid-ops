# AvoiD Raid Ops — agent/developer guardrails

Read these before making changes in this repository.

1. **Read `WCL-QUERY-PLAYBOOK.md` before any Warcraft Logs work.** WCL can be queried by exact fights, encounter, difficulty, ability, source/target, time windows, phases and `filterExpression`. Do not default to whole-report event downloads.
2. **Read `docs/IRIS-KNOWLEDGE-EVIDENCE-DOCTRINE-V1.md`, `IRIS-ARCHITECTURE.md` and `IRIS-OPERATIONS.md` before changing Iris, encounter learning, data/log controls, live polling, game knowledge or corpus-management behavior.** The doctrine is the canonical decision framework for choosing Blizzard vs WCL vs supporting providers: Blizzard supplies official published encounter semantics, WCL supplies observed combat truth, and Iris combines them for AvoiD-specific diagnosis without allowing one evidence class to impersonate another. `server/iris/capability-contract-v390.mjs` remains the machine-readable source of truth for what Iris can inspect/manage, what is partial/planned, and which autonomy/approval level applies. Do not duplicate or silently broaden those permissions in UI/runtime code.
3. **Read `docs/iris-sources/README.md` and the provider-specific file before using an external raid-data/reference site.** `server/iris/external-source-registry-v390.mjs` is the machine-readable source posture. Do not invent endpoints, promote browser-internal calls into APIs, scrape a site whose public contract does not permit it, or treat third-party derived analysis as WCL-observed truth. WoWAnalyzer/Wipefest/Archon/Lorrgs/Mythic Trap have different API/trust/licensing boundaries; preserve them.
4. **Preserve evidence classes.** Surgical WCL probes are diagnostic and must not silently count as canonical Deep reports/pulls. Incomplete Deep streams never count as complete Deep evidence.
5. **GLOBAL BOSS scope is `encounter + difficulty + partition`.** Never mix partitions. AvoiD/home reports are application/evaluation data, not boss train/holdout data.
6. **Metric/evidence contracts are versioned.** Do not silently change formulas, populations, eligibility, null policy, or evidence denominators.
7. **Use persistent evidence first.** Recompile/inspect cached evidence at 0 WCL before buying new API evidence, but external provider terms/cache headers govern what may legally/contractually be persisted. Public readability is not permission for permanent raw copies.
8. **Protect the WCL rate budget** and retain checkpoint/resume behavior. Live polling must remain compact/change-driven rather than fetching rich telemetry on every tick.
9. **UX fidelity matters.** Do not replace the existing visual system or reintroduce mock/fake interactions while wiring real data. Runtime cards must obey page ownership and the shared spacing contract.
10. **Knowledge updates never rewrite raw WCL evidence.** Activating a new Iris knowledge revision invalidates/re-derives derived products. Planned providers/workers must not be described as already implemented.
11. **Git cadence:** develop on a feature branch, validate, bump the appropriate version and open/stack the PR. **Never merge a development/stacked PR into `main` without explicit operator authorization.** Feature branches must not enable Vercel preview deployments; `main` is the production branch.
12. Never commit `.env*`, WCL credentials, Blizzard credentials/tokens, local corpus data, `node_modules`, build output, or other local secrets/state.
13. **Read `docs/IRIS-CANONICAL-DEEP-TOPUP-V1.md` before changing Deep acquisition/top-up.** The canonical Wide selection is authority after rebuild; targeted acquisition success is not the same thing as canonical Deep coverage. Top-up must close only the residual canonical deficit and must not silently expand the canonical Wide population.
14. **Read `docs/IRIS-SIGNAL-TRIAGE-V1.md` and `docs/IRIS-LOCAL-MECHANIC-SYNTHESIS-V1.md` before changing signal resolution.** Friendly-player signals are excluded from the GLOBAL BOSS denominator. Critical encounter signals must exhaust deterministic local evidence before buying more WCL evidence.
15. **Read `docs/IRIS-BOSS-AGNOSTIC-LEARNING-PIPELINE-V1.md` and the semantic-probe docs before changing Iris learning.** Production learning logic is state/evidence-driven and boss-agnostic. Do not hard-code encounter IDs, ability IDs, spell names or current-boss meaning into generic learning modules. Boss-specific fixtures may validate portability but must never become learning shortcuts.
16. **Keep learning readiness separate from publication readiness.** `learningNext` is the best next action to resolve uncertainty; `publicationNext` is the evidence breadth/validation action needed to publish confidently. Do not turn a publication-width request into the learning bottleneck when local or surgical evidence is more informative.
17. **Semantic probe execution is explicit and diagnostic.** Preview must remain 0 WCL. Execution requires the current preview fingerprint plus explicit approval, exact fight IDs, bounded calls/hourly reserve and checkpoint/resume. Semantic evidence contributes 0 canonical Deep reports/pulls, 0 direct score change and cannot automatically promote a mechanic.
18. **Package release overlay is an integer counter, not the full feature/hotfix suffix.** During the `0.3.9` release line, valid package versions use `0.3.9-<integer>-vercel.0` (for example `0.3.9-7-vercel.0`). A functional branch/version such as `v3.9.6.1` must not become `0.3.9-6.1-vercel.0`, and `v3.9.7` must not become `0.3.9-7.0-vercel.0`. Existing release-wiring tests intentionally enforce this invariant; do not loosen them to hide a bad package version.
19. **Read `docs/IRIS-BOSS-MECHANICS-CONTRACT-V3.md` and `docs/IRIS-MATCHED-NULL-BASELINE-V1.md` before changing post-verifier mechanic learning.** Local semantic flanks are diagnostic controls, not Promotion matched-null evidence. Matched controls must be selected from actual observable fight metadata, exclude target-anchor Episode neighborhoods, reject target-signal contamination after fetch, remain exact-fight/time-window bounded and never imply independent evidence groups, holdout success or automatic Promotion before those later contracts exist.
20. **Read `docs/IRIS-OFFICIAL-ENCOUNTER-KNOWLEDGE-V1.md` and `docs/iris-sources/BLIZZARD-GAME-DATA.md` before changing Blizzard/official encounter knowledge.** Blizzard Encounter Journal metadata is the authoritative published semantic hierarchy/membership for the build it exposes, but WCL remains observed combat truth. Preserve Blizzard build/namespace provenance, version compiled graphs, never treat `/spell` 403/404 as negative encounter evidence, and never let Journal metadata bypass empirical promotion gates. The broader source-selection and refresh procedure is governed by `docs/IRIS-KNOWLEDGE-EVIDENCE-DOCTRINE-V1.md`.
21. **Do not spend empirical budget on a question already answered by the correct evidence class.** For static official hierarchy/membership questions, reuse/refresh Blizzard knowledge first. For occurrence, actors, timing, causality or AvoiD execution, reuse stored WCL evidence first and acquire only the smallest missing exact-fight/window evidence. A failed matched-specificity/provenance/null gate is a stop condition unless a materially new hypothesis exists.
