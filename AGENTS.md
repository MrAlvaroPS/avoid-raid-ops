# AvoiD Raid Ops — agent/developer guardrails

Read these before making changes in this repository.

1. **Read `WCL-QUERY-PLAYBOOK.md` before any Warcraft Logs work.** WCL can be queried by exact fights, encounter, difficulty, ability, source/target, time windows, phases and `filterExpression`. Do not default to whole-report event downloads.
2. **Preserve evidence classes.** Surgical WCL probes are diagnostic and must not silently count as canonical Deep reports/pulls. Incomplete Deep streams never count as complete Deep evidence. For Deep acquisition/rebuild work also read `docs/IRIS-CANONICAL-DEEP-TOPUP-V1.md`: post-rebuild canonical coverage is authoritative and canonical Deep must come from the canonical Wide sample.
3. **Signal triage precedes new WCL spend.** Read `docs/IRIS-SIGNAL-TRIAGE-V1.md` before changing signal coverage, critical signals, relation provenance or surgical probing. Proven friendly-player signals do not belong in the GLOBAL BOSS signal denominator; friendly/noisy relations are closed rejections, not outstanding provenance work. The v1 surgical planner is dry-run only and must execute 0 WCL calls.
4. **Encounter-origin does not equal mechanic meaning.** Read `docs/IRIS-LOCAL-MECHANIC-SYNTHESIS-V1.md` before changing local mechanic synthesis. Reuse persisted Wide/Deep + validation evidence first. Structural hypotheses never silently become accepted/scoreable mechanics, never change Reliability, and never alter Boss Learned without a separately versioned promotion contract.
5. **Every Iris learning stage must be boss-agnostic.** Read `docs/IRIS-BOSS-AGNOSTIC-LEARNING-PIPELINE-V1.md`. Production GLOBAL BOSS learning code must derive targets from scoped evidence/model state, never from a hard-coded boss name, encounter ID, ability ID or spell-name semantic shortcut. New stages require a synthetic portability test with arbitrary encounter/ability IDs.
6. **Keep learning and publication decisions separate.** `learningNext` answers what best improves encounter understanding; `publicationNext` answers what breadth/gates remain before publication. Do not let a publication deficit silently overwrite the actual learning bottleneck, or let a learning recommendation silently launch broad acquisition.
7. **GLOBAL BOSS scope is `encounter + difficulty + partition`.** Never mix partitions. AvoiD/home reports are application/evaluation data, not boss train/holdout data.
8. **Metric/evidence contracts are versioned.** Do not silently change formulas, populations, eligibility, null policy, or evidence denominators. `signalCoverage`, `relationUnderstanding`, and `semanticCoverageTechnical` are distinct metrics; do not alias them.
9. **Use persistent evidence first.** Recompile/inspect cached evidence at 0 WCL before buying new API evidence.
10. **Protect the WCL rate budget** and retain checkpoint/resume behavior.
11. **UX fidelity matters.** Do not replace the existing visual system or reintroduce mock/fake interactions while wiring real data.
12. **Git cadence:** develop on a feature/fix branch, validate and bump the appropriate version. Normally prepare a PR toward `main`, but a stacked PR may target an unreleased integration branch when the user explicitly asks to accumulate related work there. **Do not merge to `main` unless the user explicitly asks for that merge in the current conversation.** Merging one feature branch into an explicitly approved unreleased integration branch does not authorize merging that integration branch to `main`. Feature branches must not enable Vercel preview deployments; `main` is the production branch.
13. Never commit `.env*`, WCL credentials, local corpus data, `node_modules`, build output, or other local secrets/state.
