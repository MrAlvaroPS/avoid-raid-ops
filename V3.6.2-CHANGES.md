# AvoiD Raid Ops v3.6.2 — Vercel build-output collision fix

## Why v3.6.1 failed

v3.6.1 combined `workflow/vite` and `nitro/vite`. Both integrations can emit Vercel Build Output functions. Vercel therefore reached the end of the build with Nitro's `__server.func/.vc-config.json` already present and the Workflow builder attempted to create the same function config again:

`Error: '/vercel/output/functions/__server.func/.vc-config.json' already exists`

This is an integration conflict, not a WCL/Blob/corpus error.

## Fix

- Upgraded Workflow SDK to `5.0.0-beta.36`, whose Nitro v3 integration is native.
- Upgraded the Nitro v3 package to the current published beta `3.0.260610-beta`.
- Removed `workflow/vite` from `vite.config.js`.
- Added `nitro.config.js` with `modules: ['workflow/nitro']`.
- Nitro is now the only component responsible for emitting the Vercel server build output.
- Workflow orchestration remains available through the same `workflow/api` `start()` call.
- Durable sleeps use explicit duration strings (`'2s'`, `'60s'`, etc.).
- Added regression coverage rejecting a future `workflow/vite` + `nitro/vite` combination.

## Product behavior

No intended UI/data behavior changes from v3.6.1. Composition's 13-class display/real class colors and the hosted corpus panel changes remain included.
